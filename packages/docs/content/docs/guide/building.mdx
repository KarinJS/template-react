开发时写的 `.tsx` 组件和 Tailwind CSS，Node 直接跑不了——发布前必须构建。本页给出可直接复制的 vite（推荐）和 tsdown 配置。

构建要产出三样：插件逻辑 JS（`src/**/*.ts` → `lib/`）、注册表 JS（`.ktr/*.ts` → `lib/`）、模板样式 CSS（→ `lib/style.css`）。

**没有 `ktr build` 命令**：构建统一走打包器，在打包配置里挂 `ktrBuildPlugin()`（`@karinjs/template-react/plugin`）即可——`buildStart` 自动刷新 `.ktr` 注册表（不用单独跑 `ktr sync`），`closeBundle` 把 CSS 编译到打包器自己的 outDir，改 outDir 不用同步改任何 ktr 配置。

## 方式一：Vite（推荐）

`ktr dev` 的开发服务器就是 Vite，生产和开发同一条管线；装 `@karinjs/template-react` 时 `vite` 和 `@tailwindcss/vite` 已随包装好，不用再装打包器。

```ts title="vite.config.ts" twoslash
import tailwindcss from '@tailwindcss/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'
import { ktrBuildPlugin } from '@karinjs/template-react/plugin'

export default defineConfig({
  // ktrBuildPlugin：buildStart 刷新 .ktr 注册表，closeBundle 编译 CSS 到 outDir
  plugins: [react(), tailwindcss(), ktrBuildPlugin()],
  // 整包模式：除 node-karin（宿主提供）外全部内联，生产环境零安装
  ssr: {
    noExternal: true,
    external: ['node-karin']
  },
  build: {
    ssr: true, // 产物跑在 karin 宿主（Node），不是浏览器
    target: 'node18',
    outDir: 'lib',
    lib: {
      entry: {
        // 你的插件入口，按需增删（karin 约定 lib/apps 结构）
        'apps/template': 'src/apps/template.ts',
        // .ktr 注册表是固定入口
        'template-registry': '.ktr/template-registry.ts',
        'mock-registry': '.ktr/mock-registry.ts'
      },
      formats: ['es']
    },
    rollupOptions: {
      external: [/^node:/, 'node-karin']
    }
  }
})
```

```bash
vite build
```

CSS 想走别的管线时传 `ktrBuildPlugin({ css: false })`。

## 方式二：tsdown（备选）

```bash
pnpm add -D tsdown
```

```ts title="tsdown.config.ts" twoslash
import { defineConfig } from 'tsdown'
import { ktrBuildPlugin } from '@karinjs/template-react/plugin'

export default defineConfig({
  entry: {
    // 入口路径必须带 ./ 前缀，否则会被当成 npm 包名解析
    'apps/template': './src/apps/template.ts',
    'template-registry': './.ktr/template-registry.ts',
    'mock-registry': './.ktr/mock-registry.ts'
  },
  plugins: [ktrBuildPlugin()],
  format: ['esm'],
  platform: 'node',
  target: 'node18',
  outDir: 'lib',
  // 注册表发现按 .js 文件名查找，ESM 产物也要固定为 .js，不要用默认的 .mjs
  outExtensions: () => ({ js: '.js', dts: '.d.ts' }),
  deps: {
    // 只有 node-karin（宿主提供）保持外部
    neverBundle: ['node-karin']
  }
})
```

```bash
tsdown
```

## 验证

构建后在 karin 里触发一次模板渲染指令，能正常出图即链路完整。两条硬性要求：`node-karin` 必须保持外部（由宿主提供）；产物里只能有一份 React（link 本地 ktr 开发时出现两份时，用 `resolve.dedupe: ['react', 'react-dom']` 去重）。

## 渲染器怎么找到产物

`createTemplateRenderer` 按约定自动发现，不需要配置：

- **注册表**：`.ktr` 源文件存在时优先（开发态），否则按 `bundledDir` 选项 → `package.json` 的 `main` 目录 → 根目录扫描发现打包产物（生产态）。
- **样式**：开发态读 dev server 实时编译的缓存，生产态读 `lib/style.css`。

产物目录叫别的名字时显式指定：`createTemplateRenderer(import.meta.url, { bundledDir: 'lib' })`。
