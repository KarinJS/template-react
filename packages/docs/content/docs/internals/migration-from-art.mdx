---
title: 从 art-template 迁移
description: '@karinjs/template-react 迁移指南：把 karin 官方 art-template（.art/.html 字符串模板）截图模板迁移到 React + Tailwind + TypeScript'
---

如果你之前的 karin 插件用官方 art-template 方案写截图模板——在 `resources/` 下放 `.art` 或 `.html` 文件，里面写 `{{title}}` 占位符，渲染时注入一份 data——这份指南会带你一步步迁移到 `@karinjs/template-react`（React + Tailwind CSS + TypeScript）。两种方案产出的都是 HTML，截图都走 karin 的 `render.render`，可以一个模板一个模板地搬，新旧并存。

<Callout type="info">
  还不会 React？先看 [React 中文官方教程](https://zh-hans.react.dev/learn)，读完"描述 UI"一章就够写模板了。不熟 Tailwind？随用随查 [Tailwind
  CSS 文档](https://tailwindcss.com/docs)，写模板大部分时间只是在 `className` 里组合现成类名。
</Callout>

## 先搞清楚：两种方案差在哪

| 维度     | art-template（旧）                                  | @karinjs/template-react（新）                                                                           |
| -------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 模板写法 | 字符串模板：HTML 里塞 `{{}}` 占位符，本质是文本替换 | 组件化 JSX（在 JavaScript 里直接写 HTML 式标签的语法）：模板是一个 React 组件，用 `defineTemplate` 注册 |
| 类型     | 没有类型，路由和字段全靠记忆，写错运行时才报错      | `defineTemplate` 全链路类型：`renderImage` 的路由有补全，`data` 写错字段编译期直接红线                  |
| 样式     | 手写 CSS，类名和覆盖关系自己维护                    | Tailwind token：`className` 里写语义化原子类                                                            |
| 预览     | 没有预览，改一次要在群里发一次指令才能看到效果      | 开发面板实时预览 + HMR（热更新：保存后浏览器里立刻刷新）                                                |
| 数据闭环 | 渲染数据散落在指令代码里，出了问题只能猜            | `mock.ts` + `data/*.json` 管理示例数据；真实渲染数据自动捕获到 `data/captured.json`，面板里直接回放现场 |

## 迁移步骤

<Steps>

<Step>

### 安装依赖

```bash
pnpm add -D @karinjs/template-react react react-dom @types/react @types/react-dom
```

<Callout type="warn">
  全部放 `devDependencies`：构建会把它们（含 react 和本工具包运行时）整体打进产物，生产环境零安装。
  关键是渲染器和组件必须同在一份产物里（包内只有一份 React 副本，hooks 才正常）；把 core 改成外部引用时，react/react-dom 才需要跟着放进
  `dependencies`。
</Callout>

成功后你会看到：`package.json` 的 `devDependencies` 里多出 `@karinjs/template-react`、`react`、`react-dom` 等条目。

</Step>
<Step>

### 新建 karin.template.ts

先在 `tsconfig.json` 的 `compilerOptions` 里补一项 `"jsx": "react-jsx"`（写 `.tsx` 组件的前提，自动运行时，组件里不需要 `import React`）；如果配置了 `include`，确认它覆盖 `src`、`template`、`.ktr` 三个目录。

然后在项目根目录新建 `karin.template.ts`。它只配置工具链自身行为，模板清单不用手写——模板、mock、JSON 数据全部按 `template/` 目录约定自动发现：

```ts title="karin.template.ts" twoslash
import { defineConfig } from '@karinjs/template-react'

export default defineConfig({
  dev: {
    port: 5180,
    host: 'localhost',
    open: false
  },
  vite: {}
})
```

成功后你会看到：项目根目录多了一个 `karin.template.ts`，它本身没有可见效果，是给第 6 步的 `ktr` 命令读的。

</Step>
<Step>

### 把一个 art 模板改写成 React 组件

新方案"目录即路由"：`template/<板块>/<模板>/index.tsx` 默认导出 `defineTemplate({...})`，注册为路由 `<板块>/<模板>`。只有 `index.tsx` 这个固定文件名会注册，裸写的其他 `.tsx` 不会。

<Tabs items={['art-template（旧写法）', 'JSX 组件（新写法）']}>
<Tab value="art-template（旧写法）">

```html title="resources/template/hello/card.html"
<div id="container">
  <h1>{{title}}</h1>
  {{if subtitle}}
  <p class="subtitle">{{subtitle}}</p>
  {{/if}}
  <ul>
    {{each items item index}}
    <li><span>{{item.label}}</span><strong>{{item.value}}</strong></li>
    {{/each}}
  </ul>
</div>
```

</Tab>
<Tab value="JSX 组件（新写法）">

```tsx title="template/hello/card/index.tsx" twoslash
import { defineTemplate, type TemplateProps } from '@karinjs/template-react'

/** 卡片模板的数据结构。 */
type HelloCardData = {
  title: string
  subtitle?: string
  items: Array<{ label: string; value: string }>
}

const HelloCard = ({ data }: TemplateProps<HelloCardData>) => (
  <div className="w-[620px] rounded-3xl border border-border bg-background p-8 text-foreground">
    <h1 className="text-3xl font-bold">{data.title}</h1>
    {data.subtitle && <p className="mt-2 text-sm text-accent">{data.subtitle}</p>}
    <div className="mt-6 grid gap-3">
      {data.items.map((item) => (
        <div key={item.label} className="flex items-center justify-between rounded-lg border px-4 py-3">
          <span className="text-sm text-muted">{item.label}</span>
          <strong>{item.value}</strong>
        </div>
      ))}
    </div>
  </div>
)

// component 标注了 TemplateProps<D>，defineTemplate 会自动推断数据类型，无需显式写泛型。
export default defineTemplate({
  name: '问候卡片',
  description: 'Tailwind 截图卡片',
  component: HelloCard
})
```

</Tab>
</Tabs>

art 语法和 JSX 的对照表，改写时照着查：

| 需求          | art-template                            | JSX                                                              |
| ------------- | --------------------------------------- | ---------------------------------------------------------------- |
| 变量插值      | `{{title}}`                             | `{data.title}`                                                   |
| 可选字段      | `{{if subtitle}}...{{/if}}`             | `{data.subtitle && <p>...</p>}`                                  |
| 列表循环      | `{{each items item index}}...{{/each}}` | `{data.items.map((item, index) => (...))}`，子元素要加稳定 `key` |
| 原样输出 HTML | `{{@ html}}`                            | `dangerouslySetInnerHTML`（慎用，见下方"常见坑"）                |
| class 属性    | `class="card"`                          | `className="card"`                                               |
| 行内样式      | `style="width:100px"`                   | 直接写 Tailwind 类 `w-[100px]`                                   |

<Callout type="warn">
  旧模板根元素上的 `id="container"` 要删掉：截图边界由框架的 HtmlWrapper 统一提供。想要圆角截图，给根元素加 `rounded-*`
  类，内容需随圆角裁剪时配合 `overflow-hidden`。
</Callout>

成功后你会看到：第 6 步启动面板后，侧边栏出现"问候卡片"模板。

</Step>
<Step>

### 把渲染数据改写成 mock.ts 或 data/\*.json

旧方案的 data 通常写死在指令代码里。新方案给数据安了两个家，可以都用：

- **TS mock**：固定文件名 `mock.ts`，具名导出，可在插件代码里 import 复用；面板中只读。

```ts title="template/hello/list/mock.ts" twoslash
// @filename: ./index.ts
export interface HelloListData {
  title: string
  users: Array<{ name: string; role: string; score: number }>
}
// @filename: ./mock.ts
// ---cut---
import type { HelloListData } from './index'

export const team = {
  title: '模板贡献榜',
  users: [
    { name: '林小满', role: '模板作者', score: 98 },
    { name: '沈括', role: '插件维护者', score: 92 },
    { name: '苏晚晴', role: '设计评审', score: 89 }
  ]
} satisfies HelloListData // 类型校验：字段写错编辑器立刻红线，且保留精确字面量类型
```

- **JSON mock**：必须放在 `data/` 子目录，可在面板里筛选、编辑、保存。

```json title="template/hello/card/data/default.json"
{
  "title": "Karin Template React",
  "subtitle": "React + Tailwind CSS + TypeScript",
  "items": [
    { "label": "渲染方式", "value": "SSR HTML" },
    { "label": "预览", "value": "Iframe 沙盒" },
    { "label": "类型", "value": "注册表驱动" }
  ]
}
```

`data/captured.json` 不用你动手：每次真实渲染时本次数据自动捕获写入（滚动覆盖单文件），开发服务器实时推送变更，面板自动刷新并选中它——线上用户发来的数据长什么样，面板里一眼回放。成功后你会看到：面板数据列表里出现 `team`、`default.json` 等条目，点选即可切换预览数据。

</Step>

### 用 renderImage 替换原来的渲染调用

旧写法是 `render.render` 直接吃模板文件加 data，art-template 在内部做文本替换：

```ts twoslash
import { render, segment } from 'node-karin'

declare const e: { reply: (content: unknown) => Promise<unknown> }
// ---cut---
// 旧写法：file 指向 .html/.art 模板，data 由 art-template 注入
const img = await render.render({
  name: 'my-plugin/hello-card',
  file: 'resources/template/hello/card.html',
  data: { title: '...', items: [] },
  selector: '#container',
  type: 'png',
  omitBackground: true
})
await e.reply(segment.image(`base64://${img}`))
```

新写法先在工具文件里用 `createTemplateRenderer` 一行装配（包根定位、配置解析、注册表加载、CSS 定位、捕获目录全部自动），只需指定 karin 领域的输出目录：

```ts title="src/utils/render.ts" twoslash
// @filename: ./src/dir.ts
/** 插件目录常量，见 src/dir.ts。 */
export const dir = { pluginName: 'karin-plugin-example' }
// @filename: ./src/utils/render.ts
// ---cut---
import path from 'node:path'
import { karinPathHtml, render, segment, type ImageElement } from 'node-karin'
import { createTemplateRenderer, type DataOf, type LoadedRegistry } from '@karinjs/template-react'
import { dir } from '../dir'

const renderTemplate = createTemplateRenderer(import.meta.url, {
  renderer: { outputDir: path.join(karinPathHtml, dir.pluginName) }
})

/** 自动注册表类型：.ktr/registry-types.d.ts 模块增强生效时为逐路由精确类型。 */
type Registry = LoadedRegistry

/** 渲染模板并交给 Karin Puppeteer 截图，返回可直接 reply 的图片消息元素；options 原样透传给 render.render。 */
export const renderImage = async <K extends keyof Registry & string>(
  templatePath: K,
  data: DataOf<Registry[K]>,
  options?: Record<string, unknown>
): Promise<ImageElement[]> => {
  const { success, htmlPath, error } = await renderTemplate(templatePath, data)
  if (!success) throw new Error(`模板渲染失败 ${templatePath}：${error}`)

  // ktr 只负责生成 HTML；截图仍交给 node-karin 的 render.render。
  const result = await render.render({
    name: `${dir.pluginName}/${templatePath}`,
    file: htmlPath,
    selector: '#container',
    type: 'png',
    omitBackground: true,
    ...options
  })

  const list = Array.isArray(result) ? result : [result]
  // Karin 的图片消息要求 base64:// 前缀，这里统一封装掉。
  return list.map((img) => segment.image(`base64://${img}`))
}
```

指令代码里就是一行调用（类型闭环：路由参数有字面量补全，`data` 类型自动跟着对应模板的 `defineTemplate` 走，写错保存时就报错）：

```ts title="src/apps/template.ts" twoslash
import { karin, type ImageElement } from 'node-karin'
import { type DataOf, type LoadedRegistry } from '@karinjs/template-react'

/** 注册表类型：.ktr/registry-types.d.ts 模块增强生效后为逐路由精确类型。 */
type Registry = LoadedRegistry
declare const renderImage: <K extends keyof Registry & string>(
  templatePath: K,
  data: DataOf<Registry[K]>,
  options?: Record<string, unknown>
) => Promise<ImageElement[]>
// ---cut---
export const templateTest = karin.command('测试模板hello/card', async (event) => {
  const images = await renderImage('hello/card', {
    title: 'Karin Template React',
    subtitle: 'React + Tailwind CSS + TypeScript',
    items: [
      { label: '渲染方式', value: 'SSR HTML' },
      { label: '预览', value: 'Iframe 沙盒' }
    ]
  })
  await event.reply(images)
  return true
})
```

路由由用户输入决定时（如 `#渲染模板 <路由>` 命令），数据可按 TS mock → `data/default.json` 的顺序解析。成功后你会看到：群里发 `#测试模板`，机器人回复一张和面板预览一致的卡片截图。

</Step>

## 常见坑

<Accordions>
<Accordion title="art 里拼 HTML 字符串的习惯，在 JSX 里怎么改？">

- **不要拼字符串当 HTML 写**。JSX 里变量放在 `{}` 里就是文本，且默认转义（`<`、`>` 转成纯文本，防止注入）。
- **条件 class 用模板字符串**：``className={`text-sm ${active ? 'text-accent' : 'text-muted'}`}``。
- **确实要渲染富文本 HTML** 才用 `<div dangerouslySetInnerHTML={{ __html: html }} />`——即 art 的 `{{@ html}}`。这段 HTML 必须可信，用户输入直接塞进去有 XSS 风险。

</Accordion>
<Accordion title="我的模板样式会和开发面板的样式冲突吗？">

不会。模板在 **iframe 沙盒**里渲染（页面里嵌的独立小窗口，里外 CSS 互不影响），面板样式进不来，你的 CSS 也出不去。主题也走明确通道且与面板外壳完全独立：框架不发明默认主题色，`ctx.theme` 可选——面板"模板主题"弹窗里显式选择后才下发，否则组件库自身主题生效；深色模式读 `ctx.theme.mode`。

</Accordion>
<Accordion title="旧模板根元素上的 id=“container” 还要保留吗？">

删掉。新方案里截图边界由框架的 HtmlWrapper 统一提供（同样是 `id="container"` 的 div，`renderImage` 的 `selector` 指的仍是它），你再写一个就成了嵌套边界，截图范围可能不对。圆角截图给根元素加 `rounded-*`（需要裁剪时配合 `overflow-hidden`）即可。

</Accordion>
<Accordion title="生产构建和旧方案有什么不同？">

旧方案的 `.html` 原样发布即可；新方案的模板是 TS 组件，发布前要编译。要点有三个：

1. **`.ktr` 注册表必须一并打包**。先 `ktr sync` 生成 `.ktr` 两个注册表，再把它们作为入口打进 `lib/`——生产环境的 SSR 直接加载 `lib/` 下的注册表，不再依赖源码目录。
2. **整包进 `lib/`，包括 react 和本工具包运行时**：只有 `node-karin`（宿主提供）和 `jiti` 保持外部；渲染器和组件同在一份产物中，包内只有一份 React 副本，hooks 才正常。切记不要"只包一半"（组件进包而渲染器外部引用），那才会出现双 React 崩溃。
3. **CSS 编成 `lib/style.css` 随包发布**：推荐用 Vite 打包 JS（和 `ktr dev` 同一条管线），样式由 `ktr build --outDir lib` 编译；完整配置和 tsdown 备选方案见 [构建与打包](/docs/guide/building)。

想理解面板、沙盒和注册表如何协作，接着读[整体架构](/docs/internals/architecture)。

</Accordion>
</Accordions>
