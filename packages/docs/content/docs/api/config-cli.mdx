## 配置文件 karin.template.ts

放在项目根目录，只配置工具链自身行为；模板、mock、JSON 数据按 `ktr/template/` 约定自动发现，**不要**手写模板清单。按 `.ts` → `.mts` → `.js` → `.mjs` 顺序查找，取第一个存在的：

```ts title="karin.template.ts" twoslash
import { defineConfig } from '@karinjs/template-react'

export default defineConfig({
  dev: {
    port: 5180,
    open: true
  }
})
```

合并优先级：**CLI 命令行覆盖 > `karin.template.ts` > 内置默认值**。

## 配置项一览

| 配置项            | 类型       | 默认值           | 说明                                                                                  |
| ----------------- | ---------- | ---------------- | ------------------------------------------------------------------------------------- |
| `dir.template`    | `string`   | `'ktr/template'` | 模板根目录，组件、mock、JSON 数据和 `style.css` 都放在这里。                          |
| `dir.assets`      | `string`   | `'ktr/public'`   | 静态资源目录；dev server 当 publicDir 服务，构建时复制到 `<产物目录>/assets`。        |
| `dir.copyAssets`  | `boolean`  | `true`           | 构建时是否复制静态资源到产物 `assets/`；资源目录本身已随包发布时设 `false` 避免重复。 |
| `dir.cssEntry`    | `string`   | 自动探测         | Tailwind 入口；默认 `<dir.template>/style.css`，缺失时自动补。                        |
| `extraStylePaths` | `string[]` | `[]`             | 额外注入 SSR HTML 的样式文件（内联进 `<style>`）。                                    |
| `dev.port`        | `number`   | `5180`           | `ktr dev` 监听端口，被占用时自动回退到下一个可用端口。                                |
| `dev.host`        | `string`   | `'localhost'`    | `ktr dev` 监听主机；暴露给局域网设 `'0.0.0.0'`。                                      |
| `dev.open`        | `boolean`  | `true`           | 启动后是否自动打开浏览器。                                                            |
| `html.headExtra`  | `string`   | `''`             | 追加到 SSR HTML `<head>` 的原始 HTML（字体 link 等）。                                |
| `vite`            | 对象或函数 | 无               | 合并到内部 Vite dev/build 配置，见下。                                                |

不可配置的固定位置：框架缓存强制为项目根的 `.ktr/`；mock 数据固定在各模板自己的 `data/` 子目录；构建产物目录由 `ktrBuildPlugin` 跟随打包器的 outDir。

### vite 扩展配置

<Tabs items={['对象形式', '函数形式']}>
<Tab value="对象形式">

```ts twoslash
import { defineConfig } from '@karinjs/template-react'
// ---cut---
export default defineConfig({
  vite: {
    resolve: { alias: { '@': '/src' } }
  }
})
```

普通的 Vite 配置对象，直接合并。

</Tab>
<Tab value="函数形式">

```ts twoslash
import { defineConfig } from '@karinjs/template-react'
// ---cut---
export default defineConfig({
  vite: ({ command, mode, config }) => ({
    define: { __DEV__: command === 'serve' }
  })
})
```

接收 `{ command, mode, config }`，返回配置对象或 Promise——按环境区分配置时用。

</Tab>
</Tabs>

## CLI 命令

安装 `@karinjs/template-react` 后通过 `pnpm ktr <命令>` 调用；`init` 和 `create` 也可以在装包前用 `npx @karinjs/template-react <命令>` 直接跑。

### ktr create

```bash
npx @karinjs/template-react create <项目名>
```

从零新建模板项目：建目录、写 `package.json` 和 `tsconfig.json`，然后走与 `init` 相同的问答。目标目录已存在且非空时报错退出。

### ktr init

```bash
npx @karinjs/template-react init
```

在**已有**的 Karin 插件项目里初始化。交互问答四项：样式方案（默认继承 HeroUI 主题，或额外生成带注释的主题变量块）、是否生成示例模板（官方 7 个）、是否生成 `src/utils/render.ts` 胶水层、开发面板端口。

产出：`karin.template.ts`、`ktr/template/style.css`、可选的示例模板与胶水层；给 `tsconfig.json` 补 `jsx: "react-jsx"`；给 `package.json` 补开发依赖和 `template` 脚本。已存在的依赖版本和同名脚本一律保留；文件名冲突时先列出清单再问是否覆盖。

<Callout type="warn">`create` 和 `init` 需要真实终端——单选框靠逐键读取 stdin，用管道或重定向喂输入会直接报错。</Callout>

### ktr sync

```bash
pnpm ktr sync
```

扫描 `ktr/template/`，生成或刷新 `.ktr/` 三个产物（模板注册表、mock 注册表、类型增强声明）。新增、删除、移动模板或 mock 之后跑；挂了 `ktrBuildPlugin()` 的打包会自动同步，不用单独跑。

### ktr dev

```bash
pnpm ktr dev --port 5180 --host localhost --no-open
```

启动开发面板（先自动执行一次 `sync`）。选项 `--port` / `--host` / `--open` / `--no-open` 只覆盖 `dev` 子配置，其余仍读配置文件。端口被占用时自动换端口，并在启动详情里打印占用进程（名称 + PID）和释放命令。

### 生产构建

**没有 `ktr build` 命令**：在 `vite.config.ts`（或 `tsdown.config.ts`）里挂 `ktrBuildPlugin()`（来自 `@karinjs/template-react/plugin`），打包时自动同步 `.ktr` 注册表并把 CSS 编译到打包器自己的 outDir。完整配置见 [构建发布](/docs/guide/building)。
