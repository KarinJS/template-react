## 配置文件 karin.template.ts

`karin.template.ts` 放在项目根目录，只配置工具链自身行为；模板、mock、JSON 数据按 `ktr/template/` 约定自动发现，**不要**手写模板清单。启动时按 `.ts` → `.mts` → `.js` → `.mjs` 顺序查找 `karin.template` 配置，取第一个存在的。用 `defineConfig` 包裹获得类型提示：

```ts title="karin.template.ts" twoslash
import { defineConfig } from '@karinjs/template-react'

export default defineConfig({
  dev: {
    port: 5180,
    host: 'localhost',
    open: false
  }
})
```

合并优先级：**CLI 命令行覆盖 > `karin.template.ts` > 内置默认值**。

## 配置项一览

| 配置项            | 类型       | 默认值           | 说明                                                                                                                          |
| ----------------- | ---------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `dir.template`    | `string`   | `'ktr/template'` | 模板根目录，组件、mock、JSON 数据和 `style.css` 都放在这里。                                                                  |
| `dir.assets`      | `string`   | `'ktr/public'`   | 静态资源目录（模板目录同级）；dev server 把它当 publicDir 服务，构建时由 `ktrBuildPlugin` 复制到 `<产物目录>/assets`。        |
| `dir.copyAssets`  | `boolean`  | `true`           | 构建时是否复制静态资源到产物 `assets/`；资源目录本身已随包发布（如 `resources/` 与 package.json 同级）时设 `false` 避免重复。 |
| `dir.cssEntry`    | `string`   | 自动探测         | Tailwind 入口；默认优先 `<dir.template>/style.css`，否则取 `dir.template` 下第一个 `.css`。                                   |
| `extraStylePaths` | `string[]` | `[]`             | 额外注入 SSR HTML 的样式文件。                                                                                                |
| `dev.port`        | `number`   | `5180`           | `ktr dev` 监听端口。                                                                                                          |
| `dev.host`        | `string`   | `'localhost'`    | `ktr dev` 监听主机。                                                                                                          |
| `dev.open`        | `boolean`  | `true`           | 启动后是否自动打开浏览器。                                                                                                    |
| `html.headExtra`  | `string`   | `''`             | 追加到 SSR HTML `<head>` 的原始 HTML。                                                                                        |
| `vite`            | 对象或函数 | 无               | 合并到内部 Vite dev/build 配置，见下。                                                                                        |

不可配置的固定位置：框架缓存强制为项目根的 `.ktr/`；mock 数据固定在各模板自己的 `data/` 子目录；构建产物目录由 `ktrBuildPlugin` 跟随打包器的 outDir（SSR HTML 默认写到 `dist/template/html`）。

### vite 扩展配置

<Tabs items={['对象形式', '函数形式']}>
<Tab value="对象形式">

```ts twoslash
import { defineConfig } from '@karinjs/template-react'
// ---cut---
export default defineConfig({
  vite: {
    resolve: { alias: { '@': '/src' } }
  }
})
```

普通的 Vite 配置对象，直接合并。

</Tab>
<Tab value="函数形式">

```ts twoslash
import { defineConfig } from '@karinjs/template-react'
// ---cut---
export default defineConfig({
  vite: ({ command, mode, config }) => ({
    define: { __DEV__: command === 'serve' }
  })
})
```

接收 `{ command, mode, config }`，返回配置对象或 Promise——按环境区分配置时用。

</Tab>
</Tabs>

## CLI 命令

安装 `@karinjs/template-react` 后通过 `pnpm ktr <命令>` 调用；`init` 和 `create` 也可以在装包前用 `npx @karinjs/template-react <命令>` 直接跑。

### ktr init

```bash
npx @karinjs/template-react init
```

在**已有**的 Karin 插件项目里初始化模板开发环境。交互问答四项：模板样式方案（使用 ktr 默认样式（继承 HeroUI 主题）/ HeroUI + 自定义主题块，后者额外生成一段带注释的主题变量块）、是否生成示例模板（官方 examples 的 7 个模板）、是否生成 `src/utils/render.ts`（把模板渲染接到 Karin 截图的辅助函数）、开发面板端口。

产出：`karin.template.ts`、`ktr/template/style.css`、可选的示例模板与胶水层；给 `tsconfig.json` 补 `jsx: "react-jsx"`；给 `package.json` 补开发依赖和 `template` / `template:build` 脚本。

**成功后你会看到**：终端逐条列出新建/覆盖/保留了哪些文件，最后提示该执行的安装命令。

<Callout>
  **已存在的东西不会被悄悄改掉**：文件名冲突时会先列出清单再问你是否覆盖，选否则只补缺失的部分；`package.json`
  里已经写过的依赖版本和同名脚本一律保留不动（包括你刻意放在 `dependencies` 里的 react）；`tsconfig.json`
  用正则插入而不是重写，注释和格式都保得住。
</Callout>

### ktr create

```bash
npx @karinjs/template-react create <项目名>
```

从零新建一个可直接跑起来的模板项目：建目录、写 `package.json` 和 `tsconfig.json`，然后走与 `init` 相同的问答和产出。省略项目名时会先问你要叫什么。目标目录已存在且非空时会直接报错退出。

**成功后你会看到**：终端提示 `cd <项目名> && pnpm install && pnpm template`。

<Callout type="warn">
  这两个命令需要真实终端——单选框和确认框靠逐键读取 stdin，用管道或重定向喂输入会拿不到按键，命令会直接报错提示而不是静默卡住。
</Callout>

### ktr sync

```bash
pnpm ktr sync
```

扫描 `ktr/template/`，生成（或刷新）`.ktr/` 三个产物：`template-registry.ts`（路由注册表）、`mock-registry.ts`（TS mock 导出 + JSON 清单）、`registry-types.d.ts`（逐路由类型的模块增强）。**成功后你会看到**：终端输出 `模板注册表已就绪：N 个模板 -> <注册表路径>`。

**什么时候要跑**：新增、删除、移动模板或 mock 之后，以及 `typecheck`、`build` 之前。如果打包配置里挂了 `ktrBuildPlugin()`（`@karinjs/template-react/plugin`），打包时会自动同步，不需要单独跑。

### ktr dev

```bash
pnpm ktr dev --port 5180 --host localhost --open
```

启动模板开发面板（会先自动执行一次 `sync`）。选项：`--port`、`--host` 覆盖监听地址，`--open` / `--no-open` 控制是否打开浏览器。**成功后你会看到**：终端清屏并打印启动详情——面板地址、模板数量、启动耗时，`open` 生效时自动打开浏览器。

<Callout>
  **端口被占用时**会自动回退到下一个可用端口，并在启动详情里额外打印是哪个进程占着（进程名 + PID）以及按当前系统该用什么命令杀掉它（Windows
  走 `taskkill`，类 Unix 走 `kill`）。
</Callout>

<Callout>
  **`open` 的生效规则**：默认 `true`；配置文件里的 `open: false` 正常生效；CLI 只有**显式传** `--open` / `--no-open`
  时才覆盖（解析器区分不了没传参和默认值，ktr 改为检查原始参数）。上面的示例写了 `open: false`，所以启动面板不会自动弹浏览器。
</Callout>

### 生产构建

没有单独的 `ktr build` 命令——构建统一走打包器：在 `vite.config.ts`（或 `tsdown.config.ts`）里挂 `ktrBuildPlugin()`（来自 `@karinjs/template-react/plugin`），打包时插件会自动刷新 `.ktr` 注册表并把模板 CSS 编译到打包器自己的 outDir。完整配置见 [构建与打包](/docs/guide/building)。
